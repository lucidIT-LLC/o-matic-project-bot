# Host capability matrix (research snapshot: 2026-11-10)

One reusable Project Bot identity serves several project contexts; Brandy's Brand Bot is a distinct lead composition. This matrix distinguishes package schema from verified host behavior. Server startup across Foundry and LucidIT was exercised in one Codex conversation on 2026-11-10; plugin handoffs and host-specific sign-in paths remain untested.

| Host | Included projection | Specialist support and inheritance | Server setup | Brand identity | State |
|---|---|---|---|---|
| ChatGPT Work Dot | Existing personal Probot Dot plus OpenAI plugin for shared skills and Server MCP. | Dot can delegate to hosted background agents; verify distinct child runs and actual tools/results per task. Plugin does not create or publish a Dot. | Connect through the Dot's supported ChatGPT plugin/MCP path; verify authenticated identity and Server grants. | Dot uses its own configured avatar; plugin supplies package branding. | Dot delegation and Server MCP access require live verification. |
| Codex | OpenAI plugin plus native `.codex/agents/` profiles. | Codex supports native subagents; plugin installation alone does not create profiles. | Remote MCP; complete user OAuth/SSO and verify active factory grants. | Profile/avatar support is host-specific. | Verify profiles, handoffs, and Server auth in the active workspace. |
| Cursor | Cursor Plugin with lead/specialist agents, skills, and MCP | Native agent components are included; prove actual lead-to-child handoff in the active Cursor surface. | MCP is configured for the parent; bind/verify every principal the runtime exposes. | Same Probot logo bundled and referenced in plugin/marketplace manifests; display unverified. | Files prepared; handoff/bindings untested. |
| Claude Code / Cowork | Claude plugin with agents, skills, and MCP | Agent components are available only on supported surfaces; test Code and Cowork separately. | Connector setup and sign-in are separate from installing the plugin. | Same Probot image is packaged; marketplace supports display name but no plugin icon field. | Files prepared; per-surface tests unrun. |
| Grok Build | Claude-compatible plugin, skills, MCP, AGENTS.md | Grok Build documents plugins and subagents and reads Claude plugin structures; validate behavior in the installed release. | Confirm OAuth support and Server endpoint reachability from runtime. | Same Probot image packaged for hosts that expose avatar upload; UI display unverified. | Projection prepared; handoff/auth untested. |
| Copilot Studio | Manual build kit for one parent and connected children | Build one Project Bot parent and one reusable child-agent graph; select the project through its Server factory context. Brandy-led Brand Bot is separate. | Add MCP to every agent needing Server tools; configure user sign-in per supported agent connection. | Shared Probot image included for agent-avatar upload; display unverified. | Copy/paste instructions only; graph not deployed. |

A project name or folder alone does not create another Project Bot. Use the same Project Bot with separate Server-backed contexts wherever the data, corpus, policies, grants, or durable state differ. A live check in one Codex conversation returned Foundry READY (11/11 roster) and LucidIT READY (9/9), both with vector retrieval and zero stale semantic-index entries. This verifies the Server context switch, not the Copilot/Cursor/Claude/Grok host adapters or child handoffs. See docs/project-context-selection.md.

Marketplace directories are separate. The GitHub repository is not a universal one-click listing. Follow `RELEASE-CHECKLIST.md` before submission.
